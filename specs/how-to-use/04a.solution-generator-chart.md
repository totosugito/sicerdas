## Generate Solution Markdown for Questions with Charts (Tahap 1: Pembahasan & Parameterisasi Chart)

---

### Versi Bahasa Indonesia

#### Opsi 1: Single Agent (Paling Hemat Token — Default & Direkomendasikan)

```bash
# Gunakan skill `exam-solution-generator`

## Folder Input

`@test` # Ganti sesuai dengan path folder kelompok soal, contoh: `@ori/001-020`

## Batasan Agent & Efisiensi Token
- **Eksekusi:** Gunakan HANYA 1 (single) main agent. Dilarang keras membuat/spawn sub-agent baru.
- **Pemrosesan:** Baca dan proses seluruh file `.md` secara sekuensial (satu per satu) dalam satu agent loop untuk menghemat penggunaan token.

## Gaya Bahasa (Tone & Persona)
- **Target Audiens:** Siswa SD, SMP, hingga SMA. 
- **Gaya Bahasa:** Sangat sederhana, kasual, ramah, dan mudah dipahami layaknya seorang guru yang mengajari muridnya. Hindari sama sekali jargon akademis yang kaku atau berbelit-belit.
- **Penjelasan Langkah:** Gunakan instruksi santai yang to-the-point. Dilarang menggunakan istilah rumit (misal: "Transformasi Ekstraksi"). Gunakan istilah sederhana (misal: "Jadikan satu ruas", "Cari titik potongnya").

## Instruksi

1. Gunakan **Folder Input** sebagai direktori kerja.
2. Baca seluruh file dengan ekstensi `*.md` yang ada di dalam subfolder `phraser/` (jika proses parafrase dijalankan) atau subfolder `ori/` pada Folder Input. Setiap file berisi **satu soal**.
3. Periksa file `imgs_summary.md` atau isi dari subfolder `imgs/` untuk mengidentifikasi apakah soal memiliki gambar diagram/grafik (chart) yang telah diproses.
4. **JIKA SOAL MEMILIKI GAMBAR CHART:**
   * **WAJIB** membaca file deskripsi `imgs/<nama_soal>.md` untuk mendapatkan konteks data, kepastian matematis (seperti fungsi kuadrat, persamaan garis), atau tabel data yang diekstrak dari gambar.
   * **WAJIB** membaca file spesifikasi ECharts JSON (file `.json` yang ada di dalam `imgs/`) terkait soal tersebut. Ekstrak informasi variabel penting dari JSON ini, seperti koordinat geometri, nilai seri data (bar/line/pie), atau rentang sumbu yang dapat diparameterisasi.
5. Buat folder `solution/` di dalam Folder Input jika belum ada.
6. Proses setiap soal secara sekuensial menggunakan **skill `exam-solution-generator`**.
7. Untuk setiap soal:
   * Hasilkan satu file Markdown lengkap berisi YAML frontmatter dan bagian pembahasan terstruktur.
   * **YAML Frontmatter:** Memuat metadata (`type`, `difficulty`, `tags`, `maxScore`, `scoringStrategy`, `requiredTier`, `isActive`) serta `variableFormulas` (minimal 5 set variasi angka dan daftar formula perhitungan intermediate dengan sintaks `mathjs` murni).
   * **PARAMETERISASI CHART (SANGAT PENTING):** Pastikan variabel-variabel yang diekstrak dari gambar (`<nama_soal>.md` dan spesifikasi `.json`) diubah menjadi parameter di dalam `variableFormulas`. Buat set variasi angka yang masuk akal dan mempertahankan esensi/bentuk logis dari grafik aslinya.
   * **Struktur Pembahasan:**
     - `## Soal`: Teks soal beserta formula TeX (`$...$` dan `$$...$$`) dan referensi gambar `![caption](../imgs/<nama_file_draw>.png)` yang merujuk pada hasil render lokal. **PENTING: Jika teks soal asli kurang jelas atau tidak lengkap, perbaiki dan perjelas teks soal berdasarkan informasi yang didapat dari gambar (spesifikasi JSON atau file markdown gambar).**
     - `## Opsi`: Daftar pilihan jawaban dengan penanda `- [x]` for jawaban benar dan `- [ ]` for jawaban salah.
     - `## Alasan`: Teks alasan (khusus untuk tipe `statement_reasoning`).
     - `## Pembahasan: Cara Konseptual`: Wajib memuat **Diketahui:** (ekstrak variabel dari teks soal dan data gambar/chart), **Ditanya:**, **Konsep Singkat:** (penjelasan teori yang sangat sederhana, analogi ramah anak SD-SMA), dan **Langkah Penyelesaian:** (langkah bertahap dengan kalimat pengantar yang santai dan mudah dicerna).
     - `## Pembahasan: Trik Cepat`: Opsional, sertakan jika ada rumus praktis.
   * **Kalimat Penutup Wajib:** Setiap bagian pembahasan wajib diakhiri dengan `Jadi, jawaban yang benar adalah ${{answer}}$.` (atau teks hasil tebal).
   * **Tanpa Referensi Opsi:** Jangan menyebutkan huruf opsi (seperti "opsi D" atau "jawaban A") karena urutan opsi diacak di database.
8. Nama file Markdown output **sama dengan nama file input `.md`**. Contoh:
   * `phraser/01_q01.md` (atau `ori/01_q01.md`) → `solution/01_q01.md`
9. Simpan seluruh file Markdown hasil pembahasan ke dalam folder `solution/`. **Jika file tujuan sudah ada, wajib ditimpa (overwrite)**. Hal ini sangat penting karena file pembahasan sebelumnya mungkin di-generate tanpa memperhitungkan informasi dari gambar.
10. Ulangi proses hingga seluruh soal selesai diproses.
11. Setelah semua soal selesai diproses, tampilkan ringkasan dalam bentuk file log format markdown yang disimpan di folder "Folder Input" dengan nama `summary.md`:
    * jumlah file Markdown yang diproses;
    * jumlah soal dengan gambar yang berhasil diparameterisasi;
    * jumlah file Markdown pembahasan yang dibuat di folder `solution/`.
```

### English Version

#### Option 1: Single Agent (Maximum Token Savings — Default & Recommended)

```bash
# Use skill `exam-solution-generator`

## Input Folder

`@test` # Change according to the question group folder path, e.g., `@ori/001-020`

## Agent Constraints & Token Efficiency
- **Execution:** Use ONLY 1 (single) main agent. Strictly avoid spawning sub-agents unless explicitly asked.
- **Processing:** Read and process all `.md` files sequentially (one by one) within a single agent loop to minimize token consumption.

## Tone & Persona
- **Target Audience:** Elementary (SD), Middle (SMP), and High School (SMA) students.
- **Tone:** Very simple, casual, friendly, and easy to understand, like a teacher explaining to a student. Strictly avoid rigid, hyper-formal, or convoluted academic jargon.
- **Step Explanations:** Use relaxed, to-the-point instructions. Do not use overly complex terms; stick to simple everyday instructions (e.g., "Combine the numbers", "Find the intersection").

## Instructions

1. Use **Input Folder** as the working directory.
2. Read all files with `*.md` extension inside the `phraser/` subfolder (if paraphrasing was run) or the `ori/` subfolder in the Input Folder. Each file contains **one question**.
3. Check the `imgs_summary.md` file or the contents of the `imgs/` folder to identify if the question has a processed chart/diagram image.
4. **IF THE QUESTION HAS A CHART IMAGE:**
   * **MUST** read the description file `imgs/<question_name>.md` to get the context, mathematical certainty (e.g., quadratic function, line equation), or data table extracted from the image.
   * **MUST** read the ECharts JSON specification file (the `.json` file inside `imgs/`) related to the question. Extract important variable information from this JSON, such as geometric coordinates, data series values (bar/line/pie), or parameterizable axis ranges.
5. Create a `solution/` folder inside the Input Folder if it does not exist yet.
6. Process each question sequentially using the **`exam-solution-generator` skill**.
7. For each question:
   * Generate one complete Markdown file containing YAML frontmatter and structured solution sections.
   * **YAML Frontmatter:** Must include metadata (`type`, `difficulty`, `tags`, `maxScore`, `scoringStrategy`, `requiredTier`, `isActive`) and `variableFormulas` (at least 5 numerical variation sets and derived calculation formulas in plain `mathjs` syntax).
   * **CHART PARAMETERIZATION (CRITICAL):** Ensure that the variables extracted from the image (`<question_name>.md` and `.json` spec) are parameterized within `variableFormulas`. Generate logical numerical variation sets that maintain the geometric essence or logical shape of the original chart.
   * **Structured Solution Sections:**
     - `## Soal`: Question text with TeX formulas (`$...$` and `$$...$$`) and image references `![caption](../imgs/<draw_file_name>.png)` referencing the locally rendered PNG. **IMPORTANT: If the original question text is unclear or incomplete, update and refine the question text based on the information provided by the image context (JSON spec or image markdown file).**
     - `## Opsi`: Option list using `- [x]` for correct options and `- [ ]` for incorrect options.
     - `## Alasan`: Reason content (for `statement_reasoning` type only).
     - `## Pembahasan: Cara Konseptual`: Mandatory section containing **Diketahui:** (extract variables from both the question text and the chart data), **Ditanya:**, **Konsep Singkat:** (very simple theory explanation, SD-SMA friendly analogies), and **Langkah Penyelesaian:** (step-by-step calculation with casual, easy-to-digest introductory sentences).
     - `## Pembahasan: Trik Cepat`: Optional section, include if a shortcut formula exists.
   * **Mandatory Conclusion Sentence:** End every solution section with `Jadi, jawaban yang benar adalah ${{answer}}$.` (or bold text result).
   * **No Option Letter References:** Never reference option letters (such as "opsi D" or "jawaban A") as option order is randomized in the database.
8. The output Markdown filename **must match the input `.md` filename**. Example:
   * `phraser/01_q01.md` (or `ori/01_q01.md`) → `solution/01_q01.md`
9. Save all enriched Markdown files into the `solution/` folder. **If the destination file already exists, you MUST overwrite it**. This is crucial because the previous solution might have been generated without accounting for the image information.
10. Repeat until all question files are processed.
11. After all questions are processed, generate a summary in the form of a markdown log file saved in the "Input Folder" named `summary.md`:
    * number of Markdown files processed;
    * number of chart questions successfully parameterized;
    * number of solution Markdown files created in `solution/`.
```
