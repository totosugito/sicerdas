## Generate Solution Master (One-Pass Orchestrator)

Tahap ini adalah versi **paling optimal** yang menggabungkan seluruh alur logika dari `04` (Text Solution), `04a` (Chart Solution), dan `04b` (Auto Illustrator) ke dalam SATU siklus jalan (One-Pass). Dengan metode ini, penggunaan token dihemat secara drastis karena AI hanya membaca mentahan soal satu kali, dan menulis solusi finalnya satu kali tanpa ada tahap menimpa (*overwrite*) atau membaca ulang.

---

### Versi Bahasa Indonesia

#### Opsi 1: Single Agent (Paling Hemat Token — Default & Direkomendasikan)

```bash
# Gunakan kombinasi skill `exam-solution-generator` dan `exam-auto-illustrator`

## Folder Input

`@test` # Ganti sesuai dengan path folder kelompok soal

## Batasan Agent & Efisiensi Token
- **Eksekusi:** Gunakan HANYA 1 (single) main agent. 
- **Pemrosesan Terpadu (One-Pass):** Baca file mentah SATU KALI, lalu hasilkan solusi akhir SATU KALI. Dilarang keras membaca file hasil output untuk diproses ulang.
- **Eksekusi Manual per Soal (CRITICAL):** Anda **DILARANG KERAS** membuat atau menjalankan script pemrograman (seperti `generate_all.py`, `processor.py`, dsb) untuk men-generate solusi banyak soal sekaligus secara otomatis. Karakteristik setiap soal sangat unik dan tidak bisa diotomatisasi secara kaku. Anda **WAJIB** menggunakan kapabilitas AI Anda untuk memproses soal secara individual satu per satu: baca 1 soal -> pikirkan & tulis solusi -> simpan file -> lanjut ke soal berikutnya.

## Gaya Bahasa (Tone & Persona)
- **Target Audiens:** Siswa SD, SMP, hingga SMA. 
- **Gaya Bahasa:** Sangat sederhana, kasual, ramah, dan mudah dipahami layaknya seorang guru yang mengajari muridnya. Hindari sama sekali jargon akademis yang kaku atau berbelit-belit. **DILARANG KERAS** menggunakan kalimat sapaan/basa-basi yang berlebihan (seperti "Halo adik-adik!", "Halo apa kabar", dll). Kata pengantar ringan seperti "Mari kita bahas" masih diperbolehkan, tapi sebaiknya langsung masuk ke inti pembahasan.
- **Penjelasan Langkah:** Gunakan instruksi santai yang to-the-point. Dilarang menggunakan istilah rumit (misal: "Transformasi Ekstraksi"). Gunakan istilah sederhana (misal: "Jadikan satu ruas", "Cari titik potongnya"). Namun **JANGAN** menggunakan analogi yang terlalu kekanak-kanakan, lebay, atau aneh (misal: "masuk ke dalam perut fungsi" untuk komposisi, atau "kurva tabrakan" untuk titik potong). Tetap gunakan istilah yang logis secara matematis tapi diucapkan dengan santai (misal: "masukkan nilai g(x) ke dalam f" atau "titik di mana kedua kurva bertemu").

## Instruksi Workflow

1. Gunakan **Folder Input** sebagai direktori kerja.
2. Baca file `.md` satu per satu dari subfolder `phraser/` (atau `ori/`).
3. Buat folder `solution/` jika belum ada.
4. **Deteksi Jalur Pemrosesan untuk Setiap Soal:**
   
   **JALUR A: Soal Memiliki Chart (Gambar dari OCR)**
   - Cek apakah di folder `imgs/` ada file `.md` atau `.json` spesifikasi ECharts dengan nama file yang identik dengan soal.
   - Jika **YA**, ekstrak variabel dan data matematis dari JSON/MD gambar tersebut.
   - Lakukan parameterisasi `variableFormulas` yang wajib mempertahankan dan menyinkronkan data grafik dengan teks soal.
   - Pertahankan referensi gambar grafik OCR tersebut (contoh: `![Ilustrasi](../imgs/<nama_file_draw>.png)`) HANYA di bagian `## Soal` sesuai dengan urutan aslinya. **DILARANG KERAS** menyisipkan atau menampilkan ulang gambar OCR asli tersebut di bagian `## Pembahasan` karena redundan (siswa sudah melihatnya di bagian soal).

   **JALUR B: Soal Teks Murni (Tanpa OCR Chart)**
   - Hasilkan solusi terparameterisasi standar (minimal 5 set variasi angka).
   - **Evaluasi Auto-Ilustrasi:** Anda **WAJIB** membuat auto-ilustrasi jika tipe soal teks termasuk dalam salah satu kategori berikut: (1) Geometri (Bangun datar/ruang, sudut), (2) Geometri Analitik & Fungsi (Perpotongan kurva, grafik fungsi garis/kuadrat/eksponen, titik koordinat), (3) Fisika Mekanika (Diagram gaya, lintasan gerak, vektor). Anda **TIDAK PERLU** membuat ilustrasi untuk tipe aljabar murni, teori murni, statistika deskriptif, dsb.
     - Jika **TIDAK PERLU**, tulis solusi murni teks.
     - Jika **WAJIB (BUTUH ILUSTRASI)**, gunakan panduan skill `exam-auto-illustrator`:
       - Buat struktur JSON ECharts dari nol untuk **setiap variasi angka** (`_auto_v1.spec.json`, `_auto_v2.spec.json`, dst). **PENTING:** Gunakan nama legend yang sangat ringkas (contoh: `"f(x)"`, `"g(x)"`, `"g1"`, `"g2"`, `"g3"` — **DILARANG** menggunakan underscore seperti `"g_1"` atau rumus persamaan `= 2^x`) dan JANGAN masukkan titik potong ke dalam legend (cukup pakai label teks di atas kanvas).
       - Jalankan script renderer lokal ECharts untuk me-render setiap JSON menjadi PNG (`node .agents/skills/exam-chart-spec-processor/scripts/render_echarts.cjs <path-json> <path-png> 450 450`).
       - Sisipkan key `img_path` (misal: `img_path: "../imgs/..._auto_draw_v1.png"`) ke dalam setiap *item* variasi di `variableFormulas.variables`.
       - Gunakan pemanggilan dinamis `![Ilustrasi Pembahasan]({{img_path}})` di dalam teks pembahasan Markdown. **PENTING:** Letakkan gambar ini di alur lokasi yang paling cocok (misalnya di bawah `**Konsep Singkat:**` atau di awal `**Langkah Penyelesaian:**`), lalu **WAJIB sinkronkan narasi dengan gambar** menggunakan notasi garis + warna + persamaannya (misal: sebutkan secara jelas: *"Pada grafik di atas, garis biru $g1$ ($y = 2$) memotong kurva merah $f(x)$, sedangkan garis hijau $g2$ ($y = -1$) tidak memotong..."*). JANGAN biarkan gambar dan teks tidak saling terhubung!

5. Simpan file Markdown hasil akhir ke dalam folder `solution/` dengan nama yang sama persis dengan file input (contoh: `solution/01_q01.md`). **PENTING:** File Markdown akhir ini WAJIB memuat secara lengkap: **YAML Frontmatter**, **`## Soal`** (teks pertanyaan yang sudah diparameterisasi), **`## Opsi`** (pilihan jawaban checkbox), dan **`## Pembahasan`** dalam satu file. Jangan hanya men-generate pembahasannya saja!
6. **Aturan Placeholder & Parameterisasi Perhitungan (CRITICAL):**
   - **DILARANG KERAS MENULIS OPERASI MATEMATIKA DI DALAM PLACEHOLDER `{{...}}` PADA TEKS / LATEX!**
     - ❌ **SALAH:** `{{d * p}}`, `{{d * p - e}}`, `{{a + b}}`, `{{x / 2}}` (Engine templating TIDAK mengevaluasi operasi matematika inline dan akan merender string literal rusak).
     - ✅ **BENAR:** Setiap langkah perhitungan perantara (*intermediate step*) **WAJIB** didefinisikan sebagai nama variabel tunggal di dalam `variableFormulas.solutions` (contoh: `d_p: "d * p"`, `d_p_minus_e: "d * p - e"`), lalu di LaTeX/teks cukup dipanggil nama variabelnya: `{{d_p}}`, `{{d_p_minus_e}}`.
   - **PENCEGAHAN DESIMAL TAK BERHINGGA (CRITICAL):** Saat mendesain variasi angka pecahan/pembagian (misal $\frac{c_{num}}{c_{den}} \cdot x$), pastikan variabel saling membagi habis (*divisible*) menghasilkan bilangan bulat bersih. Jika memang butuh pecahan, definisikan pembilang & penyebut terpisah dan render sebagai `\frac{{{num}}}{{{den}}}`.
   - **PEMBUNGKUS BASIS LATEX LOGARITMA:** Selalu bungkus basis logaritma majemuk dengan kurung kurawal ganda: `\log_{ { {{base}}^{{{a_pow}}} } }` atau `\log_{ {{a_val}} }` agar tidak terpecah oleh parser LaTeX.
7. **Konsistensi Variabel Kunci Jawaban & Kalimat Penutup Kontekstual (CRITICAL):**
   - Pastikan variabel yang digunakan pada opsi benar (`- [x] {{kunci}}`) didefinisikan secara valid di `variables` atau `solutions`.
   - Kalimat penutup pembahasan **WAJIB bersifat kontekstual** (merujuk langsung pada hal yang ditanyakan di bagian `**Ditanya:**`), contoh: `Jadi, nilai dari $\log_{{{a_val}}} f(x)$ adalah **${{kunci}}$**.`, atau `Jadi, jumlah buah milik adik sekarang adalah **${{kunci}}$ buah**.`.
   - **DILARANG KERAS** menulis `{{answer}}` jika di opsi benar menggunakan nama variabel lain (seperti `{{k_ans}}`, `{{v_ans}}`), dilarang menyebut huruf opsi (`opsi A/B/C`), dan dilarang membuat kalimat kesimpulan ganda yang membingungkan siswa.
8. Ulangi proses ini hingga seluruh soal di folder input selesai diproses.
9. Buat file `summary_master.md` di Folder Input yang merangkum: 
   - Jumlah total soal yang diproses
   - Jumlah soal yang masuk ke Jalur A (OCR Chart)
   - Jumlah soal yang masuk ke Jalur B (Teks Murni) dan berapa di antaranya yang digenerate Auto-Ilustrasinya.
```
