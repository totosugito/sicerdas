# Step 1c: Chart JSON Spec & ECharts Renderer

This document contains the usage guide for the `exam-chart-spec-processor` skill to extract chart images and geometry diagrams into pure ECharts JSON specifications, and render them locally into PNGs without using SVG.

---

## 1. Execution Guide (Single Agent Prompt)

Copy and run the following prompt template in the chat to process all images and questions in the target folder:

```bash
# Use skill `exam-chart-spec-processor`

## Input Folder

`@test` # Change according to the question group folder path, e.g., `@ori/001-020`

## Canvas Size Parameters (Standard Render Presets)
- `default` (Landscape): `500` width, `350` height — Geometry Diagrams, Physics, Flowcharts, 1-2 Quadrant Function Curves.
- `square` (Isometric 1:1): `450` width, `450` height — 4-Quadrant Cartesian Coordinates, Circles, Venn Diagrams, Matrices.
- `wide` (Horizontal): `600` width, `250` height — Number Lines, Horizontal Electrical Circuits, Timelines.
- `echarts` (Data Chart SSR): `600` width, `400` height — Bar Charts, Line Charts, Pie/Doughnut Charts.

## Typography & Default Font Size Standards
- **Global Default**: Set root `"textStyle": { "fontSize": 14 }`.
- **Formulas & Titles**: Use `"fontSize": 16` inside `title.textStyle` (e.g., italic for math equations).
- **Point / Vertex Labels**: Use `"fontSize": 14` inside `scatter.data[].label` or `series.label`.
- **Line Names / Labels**: Use `"fontSize": 14` inside `markLine.label`.
- **Axis Names & Ticks**: Use `"fontSize": 14` for `nameTextStyle.fontSize` and `"fontSize": 12` for `axisLabel.fontSize`.
## Isometric 1:1 Coordinate Scale Rule (Geometry & Function Curves)
- **Equal Aspect Ratio:** Whenever drawing Cartesian geometry, math curves (parabolas, circles, trigonometry), or coordinate diagrams, ALWAYS maintain a true **1:1 scale** so shapes do not look warped or stretched.
- **Formula:** `(xAxis.max - xAxis.min) == (yAxis.max - yAxis.min)` on the `square` preset (`450×450`).
- **Example:** If $y$ ranges from $-1$ to $9$ ($\Delta y = 10$), $x$ must range from $-5$ to $5$ ($\Delta x = 10$).

## Agent Limits & Token Efficiency
- **Execution:** Use ONLY 1 (single) main agent. Strictly forbidden to spawn new sub-agents.
- **Sequential Processing:** Read and process all images & question narratives sequentially in a single agent loop iteration.

## Instructions
1. Open the working directory at **Input Folder**.
2. Read the `.md` narrative file first to understand the context of the image (e.g., function equations, angle names, etc.).
3. View the original image in the `imgs/` subfolder.
4. If the image is a Chart (Data) or Diagram (Geometry), generate the ECharts JSON Configuration (`spec.json`).
5. **STRICT RULES:**
   - STRICTLY FORBIDDEN TO GENERATE RAW SVG CODE MANUALLY. All geometric shapes must be drawn using ECharts JSON. The renderer script will automatically generate the SVG file.
   - For Cartesian graphs and geometry diagrams, ensure the coordinate axes strictly use a **1:1 aspect ratio** (`xAxis.max - xAxis.min == yAxis.max - yAxis.min`) within the `square` canvas preset (`450x450`) to prevent distorted angles or warped shapes.
6. Create a description file `imgs/<question_name>.md` for each image containing the extracted text/data context.
7. After the `.json` is saved, render the image by running the local script using the standard canvas width and height based on the image type:
   `node .agents/skills/exam-chart-spec-processor/scripts/render_echarts.cjs <path-json> <path-png-output> <width> <height>`
8. Update the image tag in the `.md` file to reference the new `_draw.png` file.
9. Display a processing summary report in `imgs_summary.md` at the end of the run.
```

## 2. Core Processing Principles Summary

1. **Integrated Text & Image Inspection**:
   - Read the `.md` narrative before extracting data from the image to get mathematical certainty (e.g., "f(x) = x²").

2. **Output Format & Typography**:
   - **NO MANUAL SVG.** Everything must be represented in `spec.json`. The rendering script will automatically export this JSON to both PNG and SVG.
   - **Chart Data:** Extract to standard ECharts series types (`line`, `bar`, `pie`, `scatter`).
   - **Diagrams & Geometry:** Hide the axes (`"show": false`), create a Cartesian coordinate grid (e.g., -100 to 100), and plot the shape vertices using the `line` type.
   - **Typography Standards:** Root `"textStyle": { "fontSize": 14 }`. Use `16px` for `title.textStyle` formulas, `14px` for `scatter` / vertex points, `14px` for `markLine.label`, and `14px`/`12px` for axes.
   - **Points/Dots & Labels:** If the diagram has labeled dots, create a `scatter` series (e.g., `"symbolSize": 12`). For text labels, use the built-in `label` property with `fontSize: 14` (e.g., `label: { show: true, formatter: "(6, 1)", position: "top", color: "#000", fontSize: 14, textBorderColor: "#fff", textBorderWidth: 2 }`).
   - **Floating Text & Overlap Prevention:** **NEVER use the `graphic` component.** To place floating text, use the `title` component (`fontSize: 16`). **ALWAYS add `"textBorderColor": "#fff"` and `"textBorderWidth": 2` to ALL labels** to visually cut through intersecting lines with a white stroke and prevent unreadable overlaps.
   - **Canvas-Relative Grid Padding (Fill the Canvas):** The illustration must fill 85%–92% of the canvas area without bloated empty whitespace. Estimate padding proportionally relative to canvas width ($W$) and height ($H$):
     - *Geometry / Diagrams (`show: false` axes):* ~4% padding (`left/right: ~4% W`, `top/bottom: ~4% H`, e.g., 18px on 450x450, min 15px).
     - *Cartesian Graphs with Axes (`show: true` with arrows):* `left: ~6% W`, `right: ~8% W`, `top: ~9% H`, `bottom: ~7% H` (e.g. 27px, 36px, 40px, 31px on 450x450) to prevent axis arrow/name clipping.
     - *Data Charts (Bar/Line/Pie):* `left: ~7% W`, `right: ~5% W`, `top: ~8% H`, `bottom: ~7% H`.

3. **Local Rendering**:
   - The generated JSON specification does not require a live backend API for rendering.
   - Executing `node .agents/skills/exam-chart-spec-processor/scripts/render_echarts.cjs` will directly utilize ECharts SSR and Canvas to convert `spec.json` into `rendered.png` statically.

4. **Curve Smoothing**:
   - If the diagram contains curved mathematical functions (like a parabola), the AI must plot dense data points (e.g., step distance of 0.1 or 0.2) so that the ECharts `smooth: true` output looks perfectly smooth.

5. **Logging & Descriptions**:
   - Always write an `imgs/<question_name>.md` companion file storing the context or data table.
   - Always conclude the folder processing by writing a final `imgs_summary.md` log detailing what was processed.
